# ADR-103.1 — Dashboard.Paid build-time composition mechanism

- **Status:** Proposed pending Stage -1 spike (Nancy)
- **Date:** 2026-05-18
- **Stage:** 3 (sub-ADR under ADR-103)
- **Owner:** Nancy (frontend / Vite composition)
- **Mirrors:** umbrella `herald` (Modules/Dashboard)

## Context

ADR-103 commits Dashboard.Paid to extending the OSS skeleton Vue app
at build time via additive imports. The mechanism for "additive
imports" needs a sub-ADR because the choice has follow-on cost for
every paid component added later.

Nancy's Stage -1 prerequisite is a 30-minute Vite spike: prove that
`import.meta.glob('./paid-components/*.vue')` returns `{}` cleanly
when the directory doesn't exist. The spike outcome is what gates
this ADR.

This ADR is a **placeholder** pending the spike. The architectural
intent is named (option B as working assumption); the option B vs
option C decision lands when Nancy reports.

## Decision (working assumption)

### Option B — `import.meta.glob` over `paid-components/`

Dashboard.Paid's Vite config calls `import.meta.glob` against a
`paid-components/` directory that exists only in the paid repo. The
OSS skeleton's source tree omits the directory; OSS builds resolve
the glob to `{}` and ship the skeleton-only bundle. Paid builds
resolve the glob against the actual paid components and ship them
plus the skeleton.

Each paid component file exports a registration object the skeleton's
plugin loader consumes. The registration object names the capability
key the component depends on, the route slot it occupies, and the
menu entry text.

### Fallback (option C) — git submodule of OSS skeleton

If the Stage -1 spike fails — `import.meta.glob` does not return
`{}` cleanly when the directory is absent — fall back to git
submodule. Dashboard.Paid pulls the OSS skeleton as a submodule,
overlays `paid-components/` at the same path, and Vite resolves the
glob against the combined tree. Higher operational cost (submodule
discipline, dependabot story) but architecturally equivalent.

### Capability-degradation tests Echo must land in Stage 3

1. Component-mount-without-capability — paid component imports OK but
   route doesn't register because capability key absent.
2. Capability fetch 401 (paid endpoint, no token) — moved to
   Dashboard.Paid scope per ADR-103 v2.2 amendment.
3. Capability fetch 200-but-empty — server says no capabilities;
   skeleton renders.
4. Capability stale across tier upgrade mid-session — token refresh
   surfaces new capability; new route registers without page reload
   (or page reload prompt if not).
5. `import.meta.glob` on missing directory — DashboardOSS standalone
   path; bundle ships without paid components.

## Quick picture

> Picture a theatre where the main stage and the scenery shop are
> in the same building, but the scenery shop is a separate room
> behind a door. The main stage's script calls for whatever scenery
> the shop has built. If the shop is empty (OSS-only build), the
> stage runs the base script with no extra props. If the shop has
> built new pieces (paid build), the stage script picks them up
> automatically. `import.meta.glob` is the doorway. The spike tests
> whether the door stays closed cleanly when the shop room doesn't
> exist at all.

## Rationale tied to CUPID + DRY

Option B is the CUPID *Composable* call: the OSS skeleton declares
the registration shape and resolves `paid-components/*` to whatever
exists. The paid repo composes by adding files; no changes to the
skeleton are needed. The skeleton has zero coupling to the paid
component set.

Option C achieves the same composability through a heavier
mechanism (submodule). If we have to fall back, the architectural
intent doesn't change — only the operational story does.
